### ラスタライズ vs レイトレ / レイマーチ

**レイマーチング ∈ レイトレーシング**(スライド28)。共通点は「各ピクセルから**レイ(視線)を1本飛ばして**、何にぶつかるか調べる」。2D の「画面を塗る」から「目線を飛ばして当たり先の色を返す」へ視点が変わる = 3D の入り口。

違いは**衝突判定のやり方**:

| | 古典レイトレ | レイマーチ |
|---|---|---|
| 衝突判定 | 形ごとに専用の**交差式**を解析的に解く | **距離関数**でジワジワ進める |
| 球なら | レイと球の交点を二次方程式で | 距離を測って安全な分だけ進むを反復 |
| 形が変わると | アルゴリズムを書き換え | **距離関数を差し替えるだけ** |

→ 全部の形を「距離関数」という**一つの共通インターフェース**に押し込むのがレイマーチ。だから交差式が書けないフラクタルでもいける([[SDF セクションの種メモ]])。

### SDF (距離関数 `vec3 → float`)

**シーンの denotation = `vec3 → float`**(スライド29)。入力=空間の1点 `p`、出力=`p` から**一番近い物体の表面まで**の最短距離。「シーンとは何か」の答えがモデルデータではなく**空間の各点に距離を対応させる純関数**になる。世界まるごとが1つの `vec3 → float`。

- 測るのは「**立ってる1点** ↔ **一番近い物体の表面**」の距離(中心でなくフチ)。表面上なら 0、外なら正、内側は慣習で負。
- 球: `f(p) = length(p) - r`。原点からの距離が半径ちょうどで 0。
- **「一番近い」が肝**: 一番近い物体まで 5m なら、どっち向きにレイが飛んでても 5m は絶対ぶつからない → 安全に 5m ジャンプできる。

#### ★ 物体は「データ」でなく「距離関数」として存在する(§4 との決定的な違い)

頂点メッシュ(§4)= 物体を**頂点座標のリスト**(頂点バッファ)としてデータで持つ。レイマーチは真逆で **物体の座標なんてどこにも持ってない。事前計算データも無い。**

```wgsl
fn sdf(p: vec3f) -> f32 {
  let center = vec3f(0.0, 0.0, -5.0);  // 球の位置は「ただの定数」(動かすなら uniform)
  return length(p - center) - 1.0;      // この式が「球がそこにある」の全て
}
```

- 幾何が **データ → コード(式)** に変わる。これが頂点メッシュからレイマーチへの一番の飛躍。
- **事前計算ゼロ**: マーチの1歩ごとに今の `p` を式に突っ込んで**生で評価し直す**(ルックアップもキャッシュも無い)。20万px × 64歩 = 1280万回評価 = 「重い」の正体。
- 動かす = 頂点でなく**関数の引数(`center` を uniform)を変える**。
- 複数物体 = 距離関数を **`min` で合成**(`min(d_sphere, d_box)` = 一番近いやつ)。座標リストは 0 個、式が増えるだけ。README 15/16(min / smooth min)。
- FP 的に: 物体の denotation が**データ構造でなく関数**。「絵 = 純関数の合成」がドンピシャで成立 → min合成・引数で変形・関数差し替えが全部効く。シェーダ生成言語の長期目標とも一番相性がいい路線 [[user-fp-pl-background]]

#### レイの向きの決まり方(カメラ = 目 + 目の前の板)

ピンホールカメラ。目(カメラ)の**少し前にスクリーンを板として浮かべる**(スライド24「1枚の板をスクリーンに見立てる」)。板はピクセルの格子。**レイの向き = 目から、そのピクセルの穴を通り抜ける向き**。物体とは無関係に、**目とピクセル位置だけで先に決まる**(盲目的に固定 → 歩いて初めて何に当たるか分かる)。

```wgsl
let ro = カメラの位置;                    // ray origin: 全ピクセル共通
let rd = normalize(vec3f(uv, -1.0));      // ray direction: ピクセルごとに違う
//                        ↑ 奥行き。ここが FOV(視野角)。11回で tan(fov/2) に。08〜09 は -1 固定でよい
```

- `uv` は中心 `(0,0)`・右上 `(1,1)`・左下 `(-1,-1)`。板を目の 1 だけ前に置き、ピクセルの3D位置 `(u,v,-1)` へのベクトルを正規化。
- 中心px → `(0,0)` → 真っ直ぐ奥 / 右上px → 右上に傾く … → 目から**扇状にレイが広がる**。これが「ピクセル間で違うのは向きだけ」の正体。
- 組み立ての順番: **①`ro`/`rd` を作る → ②`ro` から `rd` 方向へマーチ(for ループ)→ ③当たり先の色を返す**。09 で最初に書くやつ。

#### 図は3Dを潰して描いてる / 円=球の断面

- スライド50(円の図)も 24(板の図)も**同じ3Dの世界**。前者は「歩幅の説明」用に3Dを平面に潰した**断面図**(路線図みたいに)、後者は「カメラの仕組み」用の**遠近図**。世界・レイ・物体は最初から全部3D。
- **あの「円」は本当は「球」**(レイ先端を中心に全方向へ半径ぶん安全なバリア)。紙に描くと円に見えるだけ = 手法名「**スフィア**トレーシング」の由来。
- 距離関数の型 `vec3 → float`(入力が xyz の3D)からも世界が3Dなのは確定。円の図で `◉` が横移動してたのも、本当は3D空間を `(x,y,z)` で動いてる(奥行きが紙に描けないだけ)。

#### マーチのアルゴリズム(スライド36-42)

「霧の中でおじさん(距離関数)に聞きながら歩く」:
1. 今の点で距離を聞く →「5m」
2. その距離ぶん**だけ**レイを前進(5m は安全と保証済み)
3. また聞く→進む…を反復。数がどんど小さくなり `≒0` で**当たった**

- 各ステップの点のまわりに描ける**円(球)の半径 = 距離関数の値 = 安全に進める範囲**。円の中に物体はいないと保証されたバリア。
  - 動く版(sphere tracing の GIF): https://x.com/motions_work/status/694898149622550528 — スライド38-42 のアニメ。円のフチに飛び移りながら表面へ吸い寄せられる様子
- **痺れる点**: レイは緑の四角へ真っ直ぐ向かってるのに、歩幅を決めるのは進行方向にいない「黄色い球」の距離。**「進みたい方向の物体」でなく「一番近い物体」で歩幅を決める** = 突き抜けが起きない安全側の進み方(= 保守的)。フラクタルの DE を保守的に使うのと同じ理屈。

#### 並列とループの二層構造(2Dとの関節)

スライドのレイ1本の絵 = **画面のたった1ピクセルが自分の色を決める工程**。GPU はそれを全ピクセル並列で回す。骨格は 2D と同じで、`f` の中身が「1発」から「歩くループ」に太っただけ:

```
2D:        色 = f(uv)       ← ドンッで色が出る
レイマーチ: 色 = march(uv)   ← for ループを回しきってやっと色が出る
```

- **ピクセル間**: 完全独立 → **並列**(GPU が勝手に。今までと同じ、自分は書かない)。ピクセルごとに違うのは**レイの向きだけ**(カメラ位置は共通、`uv` から向きベクトルを作る → 扇状に広がる)
- **1ピクセル内のマーチ**: 前の着地点が次の出発点 → **逐次 `for`**(自分が書く)
- コスト = ピクセル数 × 1本の歩数(例 20万 × 64)。だから重いが並列で殴れる
- FP 的に: `march : uv → 色` は相変わらず**純関数**。denotation の中身がループになっただけで、`色 = f(座標)` の骨格は死んでない [[user-fp-pl-background]]
- **09 のコード予言**: 「各ピクセルの中に `for`(マーチ)が1個」。外側の全ピクセル並列は GPU 任せ、内側の `for` を自分が書く

### 距離関数 = 形の部品カタログ(スライド52-55)

**物体 = 距離関数** の直接の帰結: **描きたい形の数だけ距離関数がいる。1形 = 1式。** 形を変える手段が「距離関数を差し替える」しかない(座標データを持たないから)→ 出せる形のバリエ = 手持ちの距離関数のバリエ。前の比較表「形が変わると → 距離関数を差し替えるだけ」の正体。

- 球: `length(p) - r` / 箱: `length(max(abs(p) - b, 0.0))`(導出はややこしいので割愛><)/ トーラス・カプセル…はまた別式
- [iq の distfunctions ページ](http://iquilezles.org/www/articles/distfunctions/distfunctions.htm) = **形の距離関数レシピ集**。自分で導出せず辞書として引く。README 13(箱)/14(異なる形状)で使う。
- シーン = 部品を **`min` で合成**して作る(下の CSG 合成へ)。部品が多いほど作れる形が増える。

### CSG 合成 (min / max)(スライド68-70)

距離関数を **`min`/`max` で合成するだけで CSG(集合演算)ができる**。`d1`=箱, `d2`=球 として:

| 演算 | 式 | 意味 |
|---|---|---|
| 和集合 union | `min(d1, d2)` | くっつける(一番近いやつ) |
| 積集合 intersection | `max(d1, d2)` | 重なりだけ残す |
| 差集合 subtraction | `max(d1, -d2)` | d1 から d2 を刳り貫く(穴あけ) |

- BoS 12章の距離場 `min`/`max` 合成が3Dに昇格。README 15(min 合成)/16(smooth min = ぬるっと結合)。
- `min` は「一番近い物体」の定義そのもの(だからマーチと自然に噛み合う)。`-d2` で符号を反転 = 内外をひっくり返して「刳り貫き」になる。

### 無限複製 (mod)(スライド71-77)

**物体 = `p` を受け取る関数**だから、`f` に渡す**前に `p` の方を折り畳める**(= domain warp = 座標変換をレイ座標へ関数適用)。

```glsl
vec3 onRep(vec3 p, float interval) { return mod(p, interval) - interval * 0.5; } // 空間を1タイルに巻く
float distScene(vec3 p) { return distSphere(onRep(p, 4.0), 1.0); }               // 球1個の式で無限個
```

- `mod(p, interval)` がどんなに遠い `p` も 0〜interval の1マスに畳み込む → **球の式は1個なのに無限に並ぶ**。
- **データ(頂点)では不可能**(頂点∞でメモリ死)。**関数なら入力座標を折り畳む1行で無限**。「物体=データでなくコード」の一番の配当。BoS 9章 `fract`/タイルの3D版。README 12。

### 陰影 (法線 = 距離場の勾配 ∇f)

**対になる美しい話(スライド56-61)**: 衝突「した/しない」だけだと**シルエット(真っ黒)しか出ない**。陰影には**法線**がいる(`diffuse = clamp(dot(light, normal), 0.1, 1.0)`)。

- **形の定義(距離関数)は形ごとに専用。でも法線は全形共通。**

| | 形の定義 | 法線(陰影に必要) |
|---|---|---|
| 古典レイトレ | 形ごとに専用 | **形ごとに専用**(球=中心を引く / ポリゴン=辺の外積)😫 |
| レイマーチ | 形ごとに専用 | **どんな形でも同じ = 距離関数の勾配 ∇f** 😄 |

- レイマーチは距離関数を差し替えても**陰影コードは1バイトも変えなくていい**。README 10(法線の算出)= `∇f` を近傍サンプリングの数値微分で取る。§4 頂点メッシュの「法線 = 変形関数の導関数」と発想が同じ(対象が頂点 → 距離場)[[user-fp-pl-background]]

#### 1つの `f` から「値」と「勾配」の2本を引く

物体 = 距離関数 `f : vec3 → float` を、カメラから光線を追ってシミュレーションする。同じ `f` から2つを引き出す:

```
物体 = 距離関数 f : vec3 → float
  ├─ 値 f(p)    … マーチに使う(当たるまで)。「あと何m?」= スカラー。法線は不要
  └─ 勾配 ∇f(p) … 陰影に使う(当たった後)。= 法線ベクトル
```

- 順番が肝: **マーチ本体は値(数)だけで動く。法線が要るのは「当たった後」の陰影づけだけ**(真っ黒シルエットで満足なら法線すら不要)。
- 1つの純関数がシーンの形も陰影も両方支える = [[user-fp-pl-background]] の「絵 = 純関数から全部生える」がそのまま。

#### なぜ 勾配 ∇f = 法線 なのか(スライド62-65)

- **直感**: `f` は「表面からの距離」。その値が**一番急に増える向き = 表面からまっすぐ離れる向き = 面に垂直 = 法線**。だから ∇f がそのまま外向き法線。
- **数学**: 曲面を `f(x,y,z)=0` で表すと、法線 `n = (f'x, f'y, f'z)`(= 偏微分 = 勾配)になると知られている。距離関数は「表面で 0 になる関数」= `f(x,y,z)=0` の曲面に等しい → **法線 n = 距離関数の勾配**。
- 「学校で微分は**傾き**と習ったが?」→ `y=2x` を `f(x,y)=2x-y=0` に変形すれば、2次元でも微分(勾配)は法線になる。傾きと法線は同じものの別の顔。

#### 勾配の計算 = xyz を少しずらして差分(数値微分)

解析的に微分せず、`f` を**近傍で数点サンプルして差を取る**(中心差分)。距離関数さえあれば機械的に法線が出る:

```glsl
const float EPS = 0.01;
vec3 getNormal(vec3 p) {
  return normalize(vec3(
    sceneDist(p + vec3( EPS,0,0)) - sceneDist(p + vec3(-EPS,0,0)),
    sceneDist(p + vec3(0, EPS,0)) - sceneDist(p + vec3(0,-EPS,0)),
    sceneDist(p + vec3(0,0, EPS)) - sceneDist(p + vec3(0,0,-EPS))
  ));
}
```

→ 各軸に `±EPS` ずらして `f` の差分を取り、正規化するだけ。**どんな形の `f` でもこの1関数で法線が出る**(形ごとの法線式は不要)。README 10 で書くやつ。

### 第0回の締め: 距離関数は万能(スライド66-67)

- **「距離関数を制した者がレイマーチングを制す」** — シーンの形も、合成も、変形も、陰影(∇f)も、**全部が距離関数 `f` 1本から生える**。だから発展編(05以降)の本体は「面白い `f` をどう書くか/組むか」に尽きる。
- 今日の第0回で掴んだ幹: **物体=`f` / マーチは値 `f(p)` / 陰影は勾配 `∇f(p)` / 形は `f` 差し替え / 合成は `min` / カメラは目+板で `ro`,`rd`**。ここから 08(レイ定義)→ 09(球)→ 10(法線)と写経に入る。

### 締め: SDF と 頂点(ラスタ)は敵でなく、混ぜられる

- **住み分け**: SDF は「手続き的・無限・滑らかに混ざる」形でエレガント(少コードで複雑)/ 頂点ラスタは「作り込んだ具体物を大量に速く」で実用の主役(GPU 専用 HW で速い)。どっちが賢いでなく別の刃物。
- **混ぜる糊 = デプスバッファ**。両者とも各ピクセルに `(色, 奥行き)` を書く関数 → 奥行きで前後を調停すれば1枚の絵に共存。現代エンジンの主流(UE5 Lumen は表面=ラスタ / GI・AO・影=mesh SDF)。
- three.js: `THREE.DepthTexture` + `gl_FragDepth`(プロキシメッシュにマーチを貼り深度を書けばシーングラフの一員に)。**自分の WebGPU 実装では depth texture + `@builtin(frag_depth)`** に読み替え → §4 頂点パイプラインに 09 の SDF マーチを depth 共有で合流できる(将来の hybrid の合体点)。
- FP 的まとめ: **ラスタも SDF も「`(色,奥行き)` を作る評価器」で同型**。「2D も 3D も `色 = f(座標)`」の統一が、ここで「ラスタも SDF も同じバッファに書く関数」まで広がる [[user-fp-pl-background]]

## 05 マンデルブロ — エスケープ時間は fold(1ピクセル内の畳み込み)

実装: [05-mandelbrot/main.ts](./05-mandelbrot/main.ts)。01 の `色 = f(uv)` の器の中身を複素数の反復に差し替えた回。3D ではないが、**08 以降のマーチと同型の骨格**を先取りできる。

### 幹: 各ピクセル = `p` だけをパラメータに、同じ関数を fold して1つの値を収穫する

- **各ピクセルで変わるのは `c` だけ、しかも `c = f(p)`**(`p`=ピクセル位置が唯一の自由入力)。`z₀=0`・反復ルール `z²+c`・上限360 は全ピクセル共通。→ `色 = f(座標)` が保たれる = 隣と独立 = GPU 並列がそのまま効く。
- **`for` ループ = 畳み込み(fold)**。同じ関数 `step c z = z²+c` を 0 から反復適用し、「脱出するまでの回数」を収穫。Haskell だと:

```haskell
step c z = z*z + c
escapeTime c = length . takeWhile (\z -> magnitude z <= 2) . take 360 $ iterate (step c) 0
color p     = palette (escapeTime (f p))     -- 画面 = 各 p を色に
```

コードの `for`+`break`+`j` は、この `length . takeWhile . iterate` を手で展開したもの [[user-fp-pl-background]]。

### fold が「運ぶもの」と「産むもの」

- **運ぶ状態(アキュムレータ)= `z`(平面上の位置)**。毎ステップ更新され糸のように引き継がれる。途中で捨てる。
- **産む値(収穫)= `j`(脱出までの回数、整数)**。色にするのはこっち。
- `p ─f→ c ─[iterate: z を畳み込む]→ 脱出回数 j ─palette→ 色`(状態 z は流れて消える)。

### 複素平面と複素数の必要性

- **平面の軸**: 横=実部(`z.x`)、縦=虚部(`z.y`)。普通の `y=f(x)` グラフと違い、両軸は1個の複素数の2部品。**スクリーンがそのまま複素平面**(ピクセルの居場所 = その `c` の居場所)。
- **`c` は固定点**(ピクセルの居場所、ループ中不動)/ **`z` が動く点**(原点 0 から出発、`z₁=0²+c=c` でまず c に着き、以後跳ね回る)。色は「`z` が |z|≤2 に留まるか飛び出すか」。
- **なぜ複素数か**: 心臓は `z²`。複素数の2乗 = **角度2倍・長さ2乗(回転しながら伸縮)**。この回転フィードバックがフラクタルの縁を生む。ただの2D成分ごとの2乗 `(a²,b²)` では回転が起きず模様にならない。複素数 = 「乗法(=回転+拡大)を入れた2Dの数」。

### 集合の定義と、形は `j` だけで出来る話

- **マンデルブロ集合の定義**: `z→z²+c` を `z₀=0` から反復して **`z` が発散しない(無限大へ飛ばず有界に留まる)ような `c` の集合**。有界の中身は不動点・周期振動・カオス的有界など色々だが、共通は「飛んでいかない」。集合なのは **`c`(場所)** の方(振動するのは `z`)。`|z|>2` は「一度超えたら必ず発散」の正確な脱出判定で、360回は「永遠に」の有限近似。
- **形を作るのは `j`(明るさ)だけ。色相 `h` は形に無関係**: `h = fract(time*20/360)` は `time` だけの関数 → 全ピクセルで同じ = 空間情報ゼロ(一様に染めて時間で回るだけ)。per-pixel で変わるのは `t = j/360`(明るさ)のみ。→ 白黒にしても形はそのまま。
- **`j` は平面上のスカラー場 `ℂ→ℕ`**、その等高線があのシルエットと縁の層。`色 = 色付け ∘ 場(j) ∘ 座標(f)` = BoS の「場」の骨格そのもの。**`j` は距離場(SDF)の兄弟**(距離でなく脱出回数という場)。
- **明暗の向き**: このコード(wgld)は `t=1`(有界=集合本体)が**明るい**/ 有名画像は集合が**黒**(逆)。同じ `j` の地図を、`t` か `1-t` のどちらで塗るかの違いだけ。`t=1` の領域 = 集合本体、`0<t<1` = 縁のハロー、`t≈0` = 黒背景(すぐ発散した外)。

### フラクタルの正体 = 滑らかな座標 × 暴れる判定

- **位置写像 `p→c` は連続**(ただのアフィン変換、近い `p` は近い `c`)。でも **`c→escapeTime` は境界で不連続**(隣の `c` が留まる/すぐ発散に激変)。`color = palette ∘ escapeTime ∘ f` の**真ん中だけが病的**。
- 原因は `z²` の回転フィードバックによる**指数的な鋭敏さ**(出発点のわずかな差が反復で急拡大)。「近い入力→近い出力」が破れる場所が無限に細かい = フラクタル。
- **`MAX_ITER` は画質↔速度のツマミ**: 下げる(例 360→100)と、脱出に多回数かかる縁ぎわの点を「中」と誤判定 → **集合が太り細部が潰れる**(＆ 分母も揃えないと全体が暗くなる)。**レイマーチの `MAX_STEPS` と同型**(下げすぎると遠い/かすめる面に届かず穴・欠け)。fold の上限を削ると精度↓速度↑。

### 08 以降との同型(先取りの意味)

**マーチも「各ピクセル = `rd` だけをパラメータに、`p += rd*d` を fold して、当たるまでの距離/位置を収穫」**。マンデルブロで fold の骨格を掴めば、レイマーチは「**fold の中身が距離関数に変わるだけ**」に見える。escape条件(`|z|>2`)↔ hit条件(`d≈0`)、反復上限 360 ↔ マーチ上限。[[SDF セクションの並列とループの二層構造]] の具体例。
